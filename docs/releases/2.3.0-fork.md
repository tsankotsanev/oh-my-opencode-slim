# 2.3.0 — fork channel

Published as **`@whitez/oh-my-opencode-slim`**, built on upstream
`oh-my-opencode-slim` 2.2.18. This is a *fork channel* release: a different npm
package, the same plugin.

Everything on disk keeps the upstream namespace, so an existing install keeps
working after switching channels — `~/.config/opencode/oh-my-opencode-slim.json[c]`,
the `~/.config/opencode/oh-my-opencode-slim/` prompt-override directory,
`opencode/storage/oh-my-opencode-slim/**`, the skills registry, log names and
`.opencode/oh-my-opencode-slim.json` project overrides are all unchanged. Only
the npm identity moved: the auto-update checker, `omos install` and the
generated `$schema` URL point at this package, so an update can never pull the
upstream release over the fork.

Replace the upstream entry in `opencode.json` with:

```json
"plugin": ["@whitez/oh-my-opencode-slim@latest"]
```

`omos install` recognises an existing upstream entry and replaces it, so the
plugin is never registered twice.

## What's new

- **Agent identity guard.** Every internal `prompt`/`promptAsync` call now
  passes an explicit agent, so a helper turn can no longer inherit whichever
  agent happened to be current (or none at all). System agents are denied as
  helper identities and hints are attached to user-role messages only. Two
  previously agent-less sites are fixed: the interview `notify` prompt and the
  smartfetch secondary-model helper (both fall back to `build`). A repo-wide
  scanner test keeps new call sites honest.
- **Silence detection + `Last seen`.** A background lane that OpenCode still
  reports as busy while emitting nothing for longer than `staleAfterMs`
  (default 5 minutes, minimum 10s) is flagged on the board as *status
  uncertain*, with an excerpt of what it was last doing. This catches hung
  provider streams that emit no lifecycle event at all. Lanes executing a tool,
  retrying a provider call, or awaiting a permission answer are exempt, and any
  new activity clears the flag. Implemented as an extension of the existing
  liveness poller — no second timer.
- **`omos lanes list | show | stop | say | revive`.** Inspect, steer and resume
  background lanes from a second terminal, without spending an orchestrator
  turn. Backed by a small JSON mirror of the board plus a server sidecar under
  the plugin data directory. The mirror is write-only (live lanes are rehydrated
  from the transcript); the CLI only appends intents that the plugin claims.
  `say` pins the lane's live model so a message cannot silently rewrite a
  session's model after a failover.
- **ESC / failover cascade attribution.** When the orchestrator is aborted, the
  abort cascades to the whole session tree and kills every background lane.
  Those lanes are now labelled on the board as interrupted by an abort of the
  orchestrator, with the cause (`esc` or `fallback`), stay intact, and remain
  resumable with `task_revive` or `omos lanes revive --cascade`.
- **`reviveOnCascade` (experimental, default `off`).** Optionally auto-resumes
  cascade-killed lanes 13s later through the same `task_revive` machinery. See
  the caveat below — **do not enable `auto` yet.**

## Fixed (upstream hazards, user-visible)

- **A rate-limit/auth failover aborted the orchestrator and silently killed all
  background lanes.** Foreground fallback aborts the orchestrator to re-prompt
  it on a fallback model, and that abort cascades to the whole session tree
  exactly as ESC does. Those lanes are now attributed (`killedByCascade`,
  `cause: 'fallback'`), stay revivable in place, and are recoverable with
  `omos lanes revive --cascade`. On a rate-limited provider this is the *more*
  common of the two cascade causes.
- **One abort no longer re-prompts the orchestrator once per dead lane.**
  Cascade lanes are reported through the board (grouped, free) instead of N
  synthesized `<task>` failures.

## Behavior changes vs upstream 2.2.18

- **`task_status.possibly_stuck` has a new definition.** It is now the board's
  silence flag — silent for at least `staleAfterMs` (default 5 minutes) with the
  tool-executing, retrying and permission-awaiting exemptions — instead of a
  separate 120s activity heuristic. The duplicate activity tracker was deleted,
  so the board and `task_status` can no longer disagree. Consequence: with
  `silenceDetection: false` there is no second clock, and `possibly_stuck` is
  **always `false`**.
- **A child transport error stays an `error` record** (revivable in place) and
  carries a transport summary as its result summary, rather than being
  downgraded to *status uncertain* and later overwritten as `stopped`.
- **`session.error` records carry the real message.** A lane you stopped is
  reported as your cancellation with its actual error text, instead of a
  generic "failed: Session error".
- **New board lines.** Lane activity/`Last seen` progress, the cascade
  attribution line and its grouped summary, and the user-cancellation label.
- **New config keys:** `silenceDetection` (bool, default true), `staleAfterMs`
  (int, default 300000), `laneControl` (bool, default true), `reviveOnCascade`
  (`off` | `auto`, default `off`).
- **New files on disk:** the lane mirror and server sidecar under
  `opencode/storage/oh-my-opencode-slim/background-jobs/`. Nothing reads them
  back as a source of truth.
- **New `omos` bin** alongside `oh-my-opencode-slim`. (`omo` was deliberately
  avoided: it collides with `oh-my-opencode` and an unrelated npm `omo`.)
- **Multiplexer pane titles carry the lane alias**, so a pane maps to the alias
  `omos lanes` prints.
- **`task_revive` internals are shared** with the CLI's revive path — one
  relaunch mechanism, one notification path, no parallel tracker.

## Caveats and known limits

- **Do not enable `reviveOnCascade: auto` yet.** It is experimental. Attribution
  is heuristic, and the auto path only triggers on a literal `error` state.
  Leave it `off` and revive deliberately with `omos lanes revive --cascade`.
- **Cascade attribution is heuristic.** Two per-pane ESCs on sibling lanes
  within three seconds are indistinguishable from one ESC on the parent.
- **Second-ESC cancellation of pending restarts only works while the
  orchestrator was busy** — an idle orchestrator emits no `session.error`.
- **Multiple OpenCode servers in the same directory: last writer wins.** The
  lane mirror and sidecar are per-directory, so a second server started in the
  same project overwrites the first one's mirror. `omos lanes` then describes
  whichever server wrote last. Use one server per directory when driving lanes
  from a second terminal.
- **`omos lanes say` cannot take a lease** across processes. On a running lane
  the message is queued normally; with `--force` into an idle retained session
  it is written as a no-reply note that lands in the transcript for a later
  `task_revive` rather than starting a turn.
- **Disabling the `build` agent breaks the smartfetch helper**, which uses it as
  its fallback identity.
- **`possibly_stuck` is always `false` when `silenceDetection: false`** (see
  above) — there is intentionally no fallback clock.
